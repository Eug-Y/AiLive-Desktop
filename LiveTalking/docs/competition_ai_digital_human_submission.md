# AI数字人应用 OPC 参赛说明

## 项目口径

本项目正式名称为“AI数字人应用”，以“小微商家直播经营助手”为首个落地场景，目标是验证一条可控制的内容与互动工作流：

```text
WorkBuddy 需求拆解
    -> 脚本、测试问题、验收标准
    -> LiveTalking 数字人播报
    -> 本地意图规则
    -> 受控大模型兜底
    -> 真人接管与紧急停止
    -> 运行记录和复盘
```

教育培训、企业服务和展厅讲解属于后续场景模板，不是首阶段并列市场。

## 快速演示

1. 启动服务。
2. 打开 `http://127.0.0.1:8010/competition_ai_digital_human.html`。
3. 点击“载入参赛演示场景”。
4. 打开 `live_console.html`，连接数字人输出。
5. 展示话术、模拟评论、人工插话、打断、紧急停止和导出。

参赛演示接口：

```text
POST /api/live/competition-demo
```

该接口只允许本机或私有网络访问，写入的是合成演示数据，并在返回内容中明确提示不能当作商业结果。

## 现场演示的三类问题

| 类型 | 示例 | 预期行为 |
| --- | --- | --- |
| 资料内高频问题 | 这个助手能做什么？ | 本地规则或已审核话术快速回答 |
| 语言改写问题 | 把刚才这段说得更口语化 | 受控大模型改写，不新增事实 |
| 风险或资料外问题 | 能保证一定成交吗？ | 安全提示，要求真人确认 |

## 工程证据

- 内容资料与禁用词：`server/sales_catalog.py`
- 本地意图路由：`server/intent_router.py`
- 数字人状态机、话术队列和接管：`server/live_studio.py`
- 字幕识别与大模型兜底：`server/subtitle_ocr.py`
- TTS缓存：`tts/cache.py`
- 工作流预检与导出：`server/workflow.py`、`server/live_routes.py`
- 合成参赛场景：`server/competition_demo.py`

## 事实边界

代码和演示证明的是产品能力，不自动证明客户、收入、订单、转化率、模型准确率或行业规模。所有商业结果必须来自真实彩排、试用、访谈或合同证据。
