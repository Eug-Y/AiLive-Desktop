## 三、硬编码路径约束（改动前必读）

以下位置被脚本**写死**，移动任何一项都会让「一键启动」失效：

| 位置 | 谁在引用 | 约束 |
| --- | --- | --- |
| `一键启动AI数字人.cmd`、`停止AI直播服务.cmd` | 用户双击 | 必须在根层 |
| `tools\` | `一键启动AI数字人.cmd` 用 `%~dp0tools\...`；`停止AI直播服务.cmd` 写死绝对路径 | 必须是根层一级子目录 |
| `env\python.exe` | `tools\*.ps1` 用 `$PSScriptRoot` 的**父目录**拼接 | 必须在根层 |
| `LiveTalking\` | 同上，且 `prewarm_tts_cache.py` 用 `parents[1]` | 必须在根层 |
| `android-sdk\` | `tools\build_mobile_apk.ps1` 用父目录 + `android-sdk` | 必须在根层 |
| `server.live.stdout.log`、`server.live.stderr.log` | `tools\start_ai_live.ps1` 写死根层路径 | 必须在根层 |

判断规则：**凡是脚本用「自己所在目录的父目录」反推根路径的，其相对位置就不能变。**

| `tools\smoke\_e2e_desktop_offline.py` | 旧版离线演示自检 8 项（测 `file://` 文件本身，仍有效） | 自检脚本放 `tools\smoke\` |
| `docs\桌面版使用说明.md` | 使用 + 维护 + 排障 | 文档放 `docs\` |
| `_qa\desktop-v1\*.png` | 验收截图 17 张 | 验收记录放 `_qa\` |

两个注意点：

1. `tools\open_desktop.ps1` 现在**含中文启动器名，改成 UTF-8 with BOM + CRLF**（无 BOM 的中文 `.ps1` 会被
   PowerShell 5.1 按 GBK 解析，这是本项目踩过的真实事故，见 `tools\smoke\_check_script_encoding.py` 顶部注释）。
   三个新启动器已登记进该检查脚本的 `LAUNCHERS` 名单，`_check_script_encoding.py` 已验证全部通过。
   另外 `桌面版AI数字人.cmd` 是**纯 ASCII + CRLF**（2026-10-12 起连 PowerShell 都不再依赖）：
   2026-10-11 实测发现「UTF-8 中文 `.cmd` + `chcp 65001` + bare LF 行尾」会让 cmd 换代码页后按字节偏移读错行、
   把后面的命令切碎执行（双击等于没反应，报 `'nul' is not recognized`）；2026-10-12 又发现**批处理文件里的中文
   是按控制台代码页解码的**，在 GBK 控制台下 `tools\启动桌面应用.ps1` 这种中文路径根本解析不出来。
   现在入口 `.cmd` 只做纯 ASCII 的"找 exe 并 start"（含"已在运行就不开第二个"的判断），
   失败时给出纯 ASCII 的打包/安装命令。另外 `if (...)` 块内的 `echo` 里**不能出现括号**，
   否则 cmd 会把 `)` 当成块结束符、整个批次解析失败（实测退出码 255 + `: was unexpected at this time.`）。
2. 桌面版**没有改任何原有页面**（`live_console.html` / `live_output.html` / `accounts.html` 等一行未动），
   它只是把真实页面放进窗口 + 调用真实接口。所以原有功能的验收记录依然有效。

三条硬约束（改这块代码前务必先看 `docs\桌面应用（真桌面版）说明.md` 第十一节）：
`HostApi` 的实例属性必须下划线开头（否则 pywebview 递归进 .NET 对象图 → js_api 为空且卡几分钟）；
销毁窗口前必须先关 `confirm_close`（否则原生确认框卡住主循环）；
给 pywebview 的启动页 URL 必须传纯路径而不是 `file://`（否则 js_api 一个都不注入）。
另外打包要处理 **conda 的 DLL 搜索路径**，否则运行时报 `DLL load failed while importing _ssl / _ctypes`。
